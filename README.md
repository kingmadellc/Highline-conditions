# Highline public observation feed

This directory is an allowlist for a small independent public data repository, `kingmadellc/Highline-conditions`. It contains no Unity code, private history, artwork, account information or secrets. Publish **only** `fetch-current.py`, `check-delivery.py`, `daily-publisher.py`, `daily-checks.py`, `daily-README.md`, this README and `observations.yml` (as `.github/workflows/observations.yml`). Ignore `site/` and `__pycache__/` in that repository. Do not copy the parent authoring repository or its `.git` directory.

The endpoint is `https://kingmadellc.github.io/Highline-conditions/current.json`. It has the same scheme/host/port as the Highline game at `https://kingmadellc.github.io/Highline/`, so WebGL can use ordinary same-origin fetch. Every refresh deploys a JSON-only artifact of at most 32,000 bytes. No Unity export or existing Highline Pages artifact participates. [GitHub Pages project URL rules](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages) allow independent project sites under the same host; one site's artifact must not replace the other.

The workflow fetches on minutes 0, 7, 27 and 47 UTC and manual dispatch. Public Actions scheduling can be delayed. The standard library importer requests only fixed official NOAA URLs and validates station routing, metric/UTC headers, missing sentinels, measured CO-OPS levels (MLLW), quality flags, observation timestamps, snapshot/row agreement, hashes and output bounds. Nearshore 41113 waves are preferred; 41009 is explicitly identified when used as an offshore fallback. Wind is from 41009 and regional water level from 8721604. No forecasts, estimates or local Hightower breaking-face claims are published.

A published snapshot requires waves no older than 120 minutes. Included wind must be no older than 90 minutes; included water level must be no older than 30 minutes. Each component is the latest valid observation at or before retrieval time and within 120 minutes of the wave observation. A component may be newer than the wave because stations update at different times; these are separate regional readings, not a simultaneous instrument record. Optional components that fail are absent with `-99999` missing values. All source times remain separate. Both writer and reader enforce these gates. A generated timestamp is never substituted for an observation timestamp. Preliminary tide quality remains preliminary; flagged or inferred measurements are excluded under [NOAA's response definitions](https://api.tidesandcurrents.noaa.gov/api/prod/responseHelp.html).

On complete wave failure or invalid data, the workflow exits before artifact upload/deploy and the previous Pages deployment remains. Clients calculate freshness from real component timestamps. They can use an explicitly stale downloaded/cache snapshot for up to 24 hours, then use the selected dated offline archive, then authored conditions if the archive is unavailable. Initial deployment/network failure follows the same path. This is a last-valid immutable deployment, not a requirement to read/write back the previous public JSON or stamp it with a new date.

## Operator setup

1. Create the clean public feed repository with a minimal description, **Highline public observation feed**. Copy only the allowlist above into its initial `main` commit. Create a `delivery-activity` branch from that clean commit, used solely for `delivery-health.json` maintenance. No private authoring source or history is transferred.
2. Set Pages build type to **GitHub Actions**, not legacy branch publishing. Configure the `github-pages` environment to allow only `main`; keep or apply review rules on source `main`, no force pushes/deletions, and no approval bypass. Default Actions token permissions stay read-only. The deploy job alone has `pages:write` and `id-token:write`, as required by [GitHub's documented Pages deployment](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages). These are ephemeral built-in tokens; no PAT or new secret is needed.
3. The monthly/manual maintenance job alone has `contents:write`; it stages exactly `delivery-health.json` and pushes normally only to `delivery-activity`. This creates ordinary repository activity without bypassing source branch review, altering measurements, publishing a game, or scheduling another AI task. Protect that branch against deletion/force pushes, but do not impose a review rule that prevents its single-purpose bot updates. Its record labels itself maintenance, never successful NOAA acquisition.
4. Run `python3 check-delivery.py` locally, then manually dispatch **Publish Highline observations**. Inspect **Validate observation delivery** and **Deploy observation JSON**, and verify that **Record monthly feed maintenance** touched only its intended metadata file/branch.
5. Fetch the deployed URL anonymously from a browser on the actual game origin, with ordinary browser security. Check HTTP 200, `response.type === 'basic'`, schema, component UTC times and size. Validate the exact downloaded body with `python3 fetch-current.py --validate current.json`. Missing optional station components must display unavailable. Perform the Unity gate and hosted menu journey before calling the integrated current lookup verified.

GitHub [disables public scheduled workflows after 60 days of repository inactivity](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule). The monthly branch commit is intended to keep this actively maintained feed repository active. If permissions, platform scheduling or the maintenance job fail, the game still ages data honestly. Inspect Actions failures, enable the workflow if it has been disabled, and use manual dispatch. There is no guarantee of exact-minute scheduling or a second monitoring service.

## Local checks

```
python3 check-delivery.py
python3 fetch-current.py --output site/current.json
python3 fetch-current.py --validate site/current.json
```

The test command is offline and uses clearly synthetic small parser fixtures. Tests cover future/stale waves, missing optional sources, incorrect stations/units, QC flags, altered rows/hashes, differing timestamps, output bounds, current NDBC headers and preservation of the last valid file on failure. Fetching is explicit. The generated JSON contains only selected official rows, source URLs/hashes and up to 31 real recent tide samples, with no filled gaps. Source hashes provide reproducibility identifiers, not provider signatures.
